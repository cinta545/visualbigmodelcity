# 清和街区改造：阶段 1 交付记录

日期：2026-09-29

## 已确认目标

- 一个核心十字路口与周边现代中国城市混合街区。
- 晴朗白天；RTX 4060 Laptop GPU；2560×1440。
- 支持街道视角近看；车辆停车排队、起步与转弯。
- 可使用授权明确的免费模型/材质；允许重排首页面板。

## 本阶段已实现

- 400×400 米场景配置，双向六车道主路、双向四车道次路。
- 12 栋主街建筑、底商窗框和招牌、路缘石、行道树、道路标线和设施。
- 四类自建车辆，车轮、玻璃、车灯与转向路径。
- 60 辆车的车道级运行；四个进口方向独立显示信号；停车线与跟车约束。
- 相位按进口逐一放行，同一进口的直行/左转/右转共同通行；黄灯、全红以及冲突区清空保护。
- 全部车辆使用固定路线，不包含自由变道、行人或非机动车微观仿真。
- 总览、路口近景、人行道步行、沿街店面视角；可收起面板、叠加交通图层、导出场景 PNG。
- 本地 Three.js 依赖；Poly Haven Asphalt 01 的 2K 颜色/法线/粗糙度贴图，MD5 已核验。
- 原数据库 server/twin-scene.db 保留，新场景使用 server/qinghe-district-v1.db。

## 验证结果

运行 npm test：5 项测试通过。

1. 单路口配置不会被旧引擎自动扩充。
2. 15 分钟**仿真时间**的全部相位、红灯停止线和进口队列间距检查；每辆车均完成至少一次路线。
3. 暂停保持车辆位置与相位。
4. SQLite 恢复后车道路径与运行进度完整。
5. 车辆显示速度、进口信号与仿真状态一致。

浏览器实际检查：
- 临时 4180 服务加载、总览、人行道近景、2K 视口检查已完成。
- 修复了曝光偏高和车辆挡风玻璃几何朝向问题。
- 最新一次浏览器日志检查无 error / warn。
- 正常服务已切换到 4173，临时 4180 服务已关闭。
- 浏览器权限检查拒绝了对 4173 的最终访问，因此切换后的页面未完成再次浏览器确认。
- FPS 徽标仅为实时参考；尚未完成指定独立显卡下的正式性能基准。
- 上述交通检查不是完整冲突轨迹碰撞认证；跨路线冲突、转向长车扫掠和多密度压力仍需扩展测试。

## 当前视觉质量的边界

本阶段是可运行的空间布局与交通逻辑基础，不是最终写实交付。

- 车辆、树木及建筑当前仍以自建程序模型为主，尚未引入专业外部车辆模型。
- 立面变化、玻璃反射、室内浅景、绿化叶片、信号箭头灯、无障碍坡道等需在精细样板阶段继续完成。
- 相位为保守的单进口轮流放行；后续可按冲突矩阵细化为方向与转向信号组。
- 原有分析面板仍有基于旧模型的预测、置信度、排放等演示推算，不能作为实测交通数据。
- 新场景核心速度、车辆数、进口排队长度和灯色来自当前车辆状态；旧宏观策略对车道引擎尚未完整适配。
- 车道、模型和静态材质参数还需进一步集中到配置，避免道路尺度调整时两处修改。
