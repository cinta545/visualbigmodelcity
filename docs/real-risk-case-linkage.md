# 真实风险案例联动

首页右侧「真实风险案例」提供交叉冲突、追尾接近两类案例。柱图表示整段记录中案例所在时段，点击柱子筛选，点击案例定位两辆交通参与者。事件时刻暂停；「播放后续」回放五秒并自动停止；「五秒后」直接检查结果；「退出案例」恢复普通车辆预测。

## 数据与边界

- 四城轨迹原始记录不改写，不补轨迹、不模拟事故。
- 索引按五百毫秒扫描，使用现有三秒有向包络接触检测；同一参与者对、同一风险类型在间隔不超过一秒时合并成一个连续候选段。
- 每段取首个满足条件的时刻：预测对象具有连续三秒历史，双方具有连续五秒后续。超过二百五十毫秒的记录间断不插值。
- 这是有完整后续记录的候选子集，并非全部风险数量或事故数量。索引的源文件摘要、采样步长、合并间隔、检测参数均写入 `data/sind/cities/risk-cases.json`。
- 后续记录用于离线挑选可验证案例、播放与误差评估；不传入模型。模型请求只有城市、车辆编号和事件时刻，服务端仍执行历史截断。

## 统一联动

案例锚点固定，整段五秒回放期间不重新预测。模型仅使用已训练的论文结构实现。灰蓝代表过去轨迹、青色代表预测、白色代表已经播放到的实际后续；图表与三维采用相同编码。蓝色虚线包络外推与接近位置属于风险检测解释，不是第二种车辆轨迹预测算法。

平均偏差为当前已播放预测步与实际位置的欧氏距离均值；当前偏差为最后一个可对照步的误差，单位米。未播放的实际未来不提前显示。缺失连续真值不填零。

切换城市、选择其他车辆、使用车型筛选或关闭详情会退出案例，并清除实际后续与冻结状态。预测请求通过代次标识拒绝过期响应，包括退出后立即重新选择同一案例的情形。

## 重建与检查

`npm run cities:cases` 重建四城索引；`npm test` 验证来源、因果锚点、连续窗口、回放边界与过期响应；设置本机浏览器路径 `CHROMIUM_PATH` 后，`npm run cases:check` 检查四城页面真实模型推理、三维定位、冻结预测和实际轨迹。

模型缺失或服务不可用时显示错误原因，不使用其他轨迹方法替代。
